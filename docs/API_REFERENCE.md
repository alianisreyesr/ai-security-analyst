# API reference

The FastAPI service is available at `http://localhost:8000` in the Docker setup.
In non-production environments, interactive OpenAPI documentation is available at
`/docs`, ReDoc at `/redoc`, and the machine-readable schema at
`/openapi.json`.

Production hides those routes unless `ENABLE_API_DOCS=true`.

## Authentication and roles

When `AUTH_ENABLED=false`, requests run as a local-development administrator.
Production refuses to start unless authentication is enabled and both API keys are
configured.

When authentication is enabled, send:

```http
X-API-Key: <analyst-or-admin-key>
```

- **Public:** no key required.
- **Analyst:** either analyst or administrator key.
- **Admin:** administrator key only.
- Missing or invalid credentials return `401`; insufficient role returns `403`.

| Method | Path | Role | Request | Response / purpose |
|---|---|---|---|---|
| GET | `/health` | Public | — | `HealthResponse`; liveness check |
| GET | `/api/v1/events` | Analyst | Query: `event_type`, `source_ip`, `limit`, `offset` | Paginated `SecurityEventListResponse` |
| POST | `/api/v1/events` | Analyst | `SecurityEventCreate` | `201 SecurityEventAccepted` |
| POST | `/api/v1/ingest/batch` | Analyst | `BatchIngestRequest` | Accepted/rejected counts, event IDs, safe errors |
| POST | `/api/v1/analysis/run` | Analyst | `AnalysisRunRequest` | Deterministic `AnalysisRunResponse` |
| POST | `/api/v1/threats/{threat_id}/analysis` | Analyst | — | Stored AI/fallback `ThreatAnalysisResponse` |
| GET | `/api/v1/threats` | Analyst | Query: `severity`, `source_ip`, `rule_id`, `q`, `start`, `end`, `limit`, `offset` | Paginated threats with MITRE mappings |
| GET | `/api/v1/threats/{threat_id}/timeline` | Analyst | Query: `limit`, `offset` | Supporting security events |
| GET | `/api/v1/threats/sources/statistics` | Analyst | Query: `limit` | Threat counts and maximum risk by source |
| POST | `/api/v1/threats/{threat_id}/reviews` | Analyst | `ThreatReviewCreate` | `201 ThreatReviewResponse` |
| GET | `/api/v1/threats/{threat_id}/reviews` | Analyst | — | `ThreatReviewListResponse` |
| GET | `/api/v1/threat-intel/reputation/{ip_value}` | Analyst | — | Cached/provider `ReputationResponse` |
| GET | `/api/v1/threat-intel/threats/{threat_id}/reputation` | Analyst | — | Reputation for a threat source |
| POST | `/api/v1/analytics/rebuild` | Admin | `AnalyticsRebuildRequest` | Rebuilt historical snapshots |
| GET | `/api/v1/analytics/sources/{source_ip}/anomaly` | Analyst | Query: `granularity`, `lookback` | Baseline and explainable anomaly score |

## Core request schemas

### SecurityEventCreate

```json
{
  "timestamp": "2026-09-22T12:00:00Z",
  "source_ip": "203.0.113.42",
  "destination_ip": "10.0.0.5",
  "source_port": 54000,
  "destination_port": 22,
  "protocol": "TCP",
  "event_type": "authentication_failure",
  "username": "admin",
  "source": "linux_ssh",
  "raw_payload": {"synthetic": true}
}
```

`timestamp`, `event_type`, and `source` are required. IP addresses must be
valid, ports must be between 0 and 65535, and unknown top-level fields are rejected.

### BatchIngestRequest

```json
{
  "format": "json",
  "content": "[{\"timestamp\":\"2026-09-22T12:00:00Z\", ...}]"
}
```

`format` is one of `json`, `csv`, `log`, or `txt`. The content field is a
string and is limited by `MAX_BATCH_CONTENT_CHARS`; parsed rows are limited by
`MAX_BATCH_ROWS`.

### AnalysisRunRequest

```json
{"limit": 5000}
```

`limit` is between 1 and 10,000. The response includes threat ID, rule ID, title,
source IP, risk score, severity, event IDs, and rule evidence.

### ThreatReviewCreate

```json
{
  "disposition": "needs_review",
  "rationale": "Validate the source against approved maintenance activity.",
  "reviewer": "analyst@example"
}
```

Disposition is `likely_false_positive`, `confirmed_suspicious`, or
`needs_review`.

### AnalyticsRebuildRequest

```json
{
  "granularity": "hour",
  "start": "2026-09-21T00:00:00Z",
  "end": "2026-09-22T00:00:00Z"
}
```

Granularity is `hour` or `day`.

## Response conventions

- Validation failures return `422`.
- Missing resources return `404`.
- Oversized requests return `413`.
- Rate limiting returns `429`.
- `X-Request-ID` may be supplied by the client and is returned for traceability.
- AI and reputation integrations have deterministic disabled/unavailable behavior;
  their output never replaces rule evidence or risk scoring.

The OpenAPI document generated by the running application remains the canonical
field-level schema.
